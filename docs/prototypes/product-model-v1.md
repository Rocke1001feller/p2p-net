# p2p-net 产品模型 v1（2026-09-28 梳理）

## 0. 定位（经 9-28「Kimi Code 接管工作台」事件实证）

p2p-net = **纯网络基础设施**。它不 care、不干涉设备上跑什么服务；任何 web 服务都可被它托举。
3001 没起来是 3001 自己的事；Kimi Code 57255 被托举起来，恰好证明了承载力的通用性。

## 1. 三级对象模型

```
账号（Supabase user）          ← 计费/归属最小单元（未来 Stripe/Dodo 挂载点）
  └── 设备（device）            ← 一台机器 = 一个 group；有且仅有一个 p2p-net 实例
        └── 服务（service）      ← 设备上自动发现的 web 服务 = 一个 tab
```

- **账号**：唯一用户维度。登录、配对、付费都以它为中心。
- **设备**：自动上线/下线；多端同时在线（手机看电脑、平板看 NAS）。
- **服务**：**自动发现、自动挂载、默认全部可见**；用户只能做减法（隐藏/不挂载），减法是挂载之后的事。
- **网络层**（P2P > 隧道 > 中继）对上层完全透明，只在徽章上留一个诚实标签。

## 2. 浏览器隐喻（用户图示定调）

| 浏览器概念 | p2p-net 对应 |
|---|---|
| Tab Group（一台设备一组） | 设备 |
| Tab | 服务 |
| 地址栏/书签 | 服务清单（自动发现，无需手工添加） |
| 关闭/隐藏 tab | 用户的减法操作（唯一入口） |

## 3. 现行 UI 差距（9-28 取证结论）

| 现状 | 目标 |
|---|---|
| 工作台只直载「被裁决的一个」服务，其余静默隐身 | 所有服务全部可见、可切换（tab 化） |
| 服务列表只在 `__p2pNetDebug` 里 | 服务清单是一等公民 UI |
| console 单端口锚定（防劫持） | 保留锚定作为「默认首页服务」，但不再遮蔽其余服务 |
| 设备列表仅用于连接入口 | 设备 = group，承载其下的服务集合 |
| 无付费概念 | 账号级订阅（设备数/服务数/流量分档） |

## 4. 商业化骨架（账号为付费最小单元）

- **套餐维度候选**：设备数上限、服务数上限、中继流量额度（P2P/隧道不计费或高额度，中继按 GB——成本模型 §6.1 已有真机字节计量回填）。**套餐只有两档：Free / Pro**（2026-09-28 用户裁决：不设 Team 档）。
- **支付通道**：Stripe（海外）/ DodoPayments（MoR 省心）二选一或并存；Supabase 账号 uid ↔ Stripe customer 映射；Webhook 落订阅状态表。
- **目标客群**：创业团队「一站式商业化」——他们部署 p2p-net 即可把自己的服务暴露给自己的用户，我们收基础设施订阅费。
