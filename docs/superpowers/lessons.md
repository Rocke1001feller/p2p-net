### ③ 2026-09-25「Mac 大概率休眠」误判

- **规则**：可探测的事禁止猜——先探测后断言，证据先行。

### ④ shell cwd 纪律

- **规则**：每个终端命令显式传 cwd，绝不跨仓操作。
- **根因**：多仓并存（DevAnyWhere 主仓 ↔ PeerToPeer-net 独立仓），shell 的隐式 cwd 极易指错仓库，跨仓读写即事故。
- **关联测试/门禁**：流程纪律（本册登记；并行子代理任务书强制条款——一切命令显式 cwd，一切改动限定在指派 worktree 内）。

### ⑤ debugging 优先原则

- **规则**：凡能快速定位问题的可观测性建设一概必做、无需请示。
- **根因**：前项目死因——复杂度失控 + 量化信息不可知不可控，导致无法 debug。可观测性不是锦上添花，是复杂系统的生存条件。
- **关联测试/门禁**：流程原则，由「计划自审 checklist」第 3 问机械执行（可观测性钩子是否就位）。

### ⑥ 狗粮纪律

- **规则**：本包自产运维能力（如 `p2p-net service install` 的 launchd/systemd 监管）开发机必须先用——「实现-采用」缺口即事故。
- **根因**：`src/cli/service.ts` 早已实现 service install，但开发机从未安装——host 进程无人监管，死了又死。能力只「实现」不「采用」，等于没有。
- **关联测试/门禁**：采用清单——每项自产运维能力落地时，登记其「开发机采用状态」；未采用即未交付，本册条目为督促依据。

### ⑦ 测试隔离

- **规则**：套件必须在常驻服务运行下全绿；测试绑固定端口即债。
- **根因**：开发机常驻 host 占用 `contracts/ports.json` 的 CONTROL/DISCOVERY/DOCS 端口（19727–19729）；测试绑固定端口即与常驻服务冲突，套件在真实开发环境跑不绿，绿灯变成奢侈品。
- **关联测试/门禁**：✅ `mech/testiso` 已合入 main（常驻 host 运行中 `npm run test:parallel` 连续 4 次全绿）：`control.ts` 工厂可注入端口、测试全量 `listen(0)` 动态化；watchdog 两例竞争根修（原断言未动）；scanner 加注入缝 + whitelist 甄别测试标记。新增测试一律动态端口，禁止绑 19727–19729。
